仅需要下载通知时用 [Webhook](webhook.md)，不必开启本页的在线同步，也不用填写 ani-rss 地址和登录凭据。想一次导入已有的整张订阅表，再选择下面的在线同步或离线导入。

如果你已经在用 [ani-rss](https://github.com/wushuo894/ani-rss) 追番，那「我在追哪些番、下到第几集」这份名单其实已经存在了 ——
没必要再在群里一部部 `/追番`。打开这个功能，插件会定时去读 ani-rss 的订阅列表，把它变成自己的追番表。

**设计上只做三件事，也只做这三件事：**

| 约束 | 为什么 |
| --- | --- |
| **单向只读** | 绝不回写 ani-rss。下载器的配置是你的资产，插件没有资格改 |
| **不自动删** | ani-rss 里删掉的条目，这边只报「已失联」并保留记录。地址填错一次就清空整张追番表，代价太大 |
| **进度只往前** | ani-rss 的「已下载到第几集」和你「实际看到第几集」是两件事，取两者较大值 |

## 两条路，选一条就行

| 通路 | 适合谁 | 代价 |
| --- | --- | --- |
| **在线同步** | AstrBot 与 ani-rss 在同一台机器、同一个局域网，或者已经用 Tailscale / frp 打通了 | 服务器必须能访问到 ani-rss 的端口 |
| **离线导入** | ani-rss 在自己电脑上、AstrBot 在公网服务器 —— 这是最常见的情况 | 每次手动搬一份 JSON，但不用开端口、不用填任何凭据 |

两条路**落库结果完全一样**（走的是同一段代码），区别只在「这份名单从哪来」。
先按下面三步试在线同步，连不上就翻到「离线导入」。

> **名单建好之后，日常进度交给 Webhook 更省事。** 让 ani-rss 每下完一集主动推一条过来，
> 群里当场收到卡片、追番进度立刻往前推，不必等下一次同步。
> 配法见 [Webhook 接入](webhook.md)。

## 三步配好（在线同步）

**1. 拿凭据**

ani-rss 设置页里复制 API Key，填进 `anirss_api_key`。没开 API Key 的话也可以填 `anirss_username` + `anirss_password`，
插件会自己登录换 token（公网访问无论用哪种凭据都应使用 HTTPS 或可信 VPN）。

**2. 填地址**

`anirss_base` 填 `http://<ani-rss主机>:7789`，末尾的 `/api` 可以省略。
AstrBot 跑在服务器、ani-rss 跑在自己电脑上时，要填一个服务器能访问到的地址 —— 局域网 IP 或打了洞的公网地址。
填完先发 `/anirss test`，会直接告诉你连不连得上、认到几条订阅。

**3. 指定同步进哪个会话**

追番表是**按会话分开存**的，所以必须告诉插件同步到哪儿。`anirss_sync_targets` 填完整会话标识，
形如 `default:GroupMessage:123456`（管理页的「播报」视图里能直接看到候选会话）。
填完打开 `anirss_enabled`，之后每 `anirss_sync_interval_minutes` 分钟自动同步一次（默认 60，填 `0` 表示只手动同步）。

## 离线导入（连不上时用这个）

ani-rss 一般跑在自己电脑上，AstrBot 多半在公网服务器上 —— 服务器要主动连回家里的 7789 端口，
就得内网穿透或在路由器上开端口映射。**为了同步一张追番表把下载器暴露到公网，不划算。**

所以还有这条路：把 ani-rss 的响应搬过来。全程不需要插件能访问到 ani-rss，也不用填 API Key。

**1. 在跑着 ani-rss 的那台电脑上执行**

```bash
curl -s -X POST "http://127.0.0.1:7789/api/listAni" -H "api-key: 你的APIKey" -o ani.json
```

端口改过就照自己的填；ani-rss 没启用鉴权的话把 `-H` 那一段去掉。
Windows 上 PowerShell 自带 `curl.exe`，直接跑这条即可。

**2. 打开管理页的「同步」视图 → 「离线导入」**

把 `ani.json` 的内容整份粘进文本框，点「导入这份数据」。
带 `code` / `data` 的整份包封和里层的 `data` 两种都认，不用手动抠。

**3. 落到哪些会话**

和在线同步同一份名单：`anirss_sync_targets`。同一页上面就能改。

> 导入是**合并**而不是覆盖：本地没有的补上、进度只往前推、本地多出来的一律保留。
> 导入过的条目同样会记下认领关系，之后哪天打通了网络改走在线同步，也不会重复插一条。

## 同步到底做了什么

```
ani-rss 订阅列表
  ├─ 药屋少女的呢喃 第二季   已下载 7 集   bgm.tv/subject/425909
  └─ 无路可逃                已下载 3 集   bgm.tv/subject/512345
          │
          │  先看认领关系，没有再按标题找（精确 → 包含）
          ▼
追番表（anirss_sync_targets 指定的会话）
  ├─ 药屋少女的呢喃 第二季   6/24 → 7/24   ✎ 进度前进
  └─ 无路可逃                — → 3/12      ✚ 新增
```

每条条目会记一条**认领关系**（ani-rss 的条目 ID ↔ 追番记录 ID）。有了它，你在群里手动改过标题、
或者 ani-rss 那边改了番名，下一次同步也不会重复插一条新的。

## 四个开关

| 开关 | 默认 | 说明 |
| --- | --- | --- |
| `anirss_sync_watchlist` | 开 | 写进追番表并回填进度。关掉就只做连接与查看，不落库 |
| `anirss_sync_subscriptions` | **关** | 顺便建立 RSS 订阅。**多数人不该开** —— ani-rss 自己已经在轮询这些 RSS 了，插件再订一遍会收到两份通知。只有「下载归 ani-rss、通知归 AstrBot」的玩法才需要 |
| `anirss_notify_on_change` | 开 | 有变化（新增 / 进度前进 / 失联）时发一张同步账目卡；没变化时静默 |
| `anirss_verify_tls` | 开 | 只有用自签证书反代时才需要关 |

> 同步账目走的是**独立推送链**，只发到 `anirss_sync_targets` 指定的会话，绝不会混进 RSS 更新那条推送链 ——
> 那条链是给「有新集了」用的，把同步账目刷进去会吵。

## 配合 `push_only_watchlist` 的完整玩法

```
电脑上的 ani-rss 点订阅  →  插件同步进追番表  →  每日播报只播追番表里的番
```

打开 `push_only_watchlist` 后，「今日新番」播报只会列出追番表里有的番。于是整条链变成：
**追番名单在 ani-rss 维护，每日播报按同步后的追番表筛选。** 这个开关不限制 RSS 或 Webhook；它们各自按订阅与通知目标发送。

## 相关指令

```
/anirss           看同步状态：连接情况、上次同步账目、已认领的条目
/anirss sync      立刻同步一次（仅管理员）
/anirss test      只测连接，不写库（仅管理员）
```

管理页的「ani-rss 同步」视图把这些都做成了按钮：地址、凭据、目标会话、四个开关和间隔都能就地改，
还带一块**离线导入** —— 连不上 ani-rss 时粘一份导出的 JSON 就行。
