## 订阅方式

```
/sub 芙莉莲 https://mikanani.me/RSS/Bangumi?bangumiId=3141   完整地址
/sub 芙莉莲 mikan:葬送的芙莉莲                                 Mikan 搜索
/sub 每日新番 rsshub:bangumi/calendar/today                    RSSHub 路由
/sub 芙莉莲 dmhy:葬送的芙莉莲                                  动漫花园搜索
/sub 葬送的芙莉莲                                              只给名字，自动去找源
```

最后一种是推荐用法，也是默认行为：只给番名，插件会去 Mikan 找这部番收录了哪些字幕组，列出来让你挑一个。

## 为什么要挑字幕组

Mikan 的关键词搜索源会把**所有字幕组、所有语言、所有画质**的发布一起收下。
一集番同时有简体 / 繁体、720p / 1080p、内嵌 / 外挂，于是「订阅一部番」实际等于「每集被推七八条」。
因此推荐先选择字幕组：

```
你：/sub 名侦探光之美少女

Bot：名侦探光之美少女 · 找到 5 个字幕组，回复序号订阅
     1. 雪飘工作室          最近有更新
     2. Kirara Fantasia    最近有更新
     3. LoliHouse           最近有更新
     ...

你：1

Bot：已订阅 名侦探光之美少女（雪飘工作室）
     （上面那条候选列表会被自动撤回）
```

- 订上的是**单组 RSS**（`/RSS/Bangumi?bangumiId=xxx&subgroupid=yyy`）；同一组仍可能发布多个版本，见下方排除与归并说明。
- 候选列表 **3 分钟**过期，同一会话再发起一次会顶掉上一次。
- 一部番的组太多时只列前 12 个，按最后更新时间排。
- `/追番 <名称>` 之后也会跟一次同样的候选列表，回序号即可顺手订上。
- 想订阅包含全部字幕组的搜索源，把配置项 `rss_pick_source` 关掉即可。

## 排除项与同集归并

选了单组之后还是会有重复：同一个组常把同一集的**简体 / 繁体、1080p / 720p、Baha / ABEMA** 各发一遍。
插件用两个互补的手段解决 —— 排除项负责「我永远不想看到这种版本」，同集归并负责「这一集给我挑一条就好」。

### 三层排除项

过滤按这个顺序叠加，任意一层命中就直接丢掉，不推、不入库：

| 层 | 在哪里设 | 作用范围 |
| --- | --- | --- |
| **全局层** | 配置项 `global_excludes`（Dashboard / 管理页） | 所有会话、所有订阅，无条件生效 |
| **会话层** | `/sub_exclude`，或管理页的「排除项」面板 | 当前会话的所有订阅 |
| **单条订阅** | 管理页订阅行的编辑，或用 `/sub_exclude apply` 把会话词表回写进去 | 只影响那一条订阅 |

先在配置项里把「这台 Bot 一律不要的东西」设一次（比如繁体、合集），之后新加的群不用再设一遍；
个别群口味不同，再用 `/sub_exclude` 在它之上加严：

```
/sub_exclude              看两层清单与合并后的实际过滤词
/sub_exclude preset       列出内置预设，按名字勾
/sub_exclude add 繁体     加一个词（也可以直接写预设名，会自动展开）
/sub_exclude del 繁体     删一个词
/sub_exclude apply        把本会话词表刷到已有订阅上
/sub_exclude clear        清空本会话词表
```

内置预设 16 组，写预设名会自动展开成一串同义写法，省得逐条手打（同一件事字幕组能写出四五种花样，只写字面量等于没过滤）：

| 预设 | 展开成 |
| --- | --- |
| `简体` | 简体、简日、简中、CHS、`[GB`、`[SC]`、`SC]` |
| `繁体` | 繁体、繁日、繁中、CHT、BIG5、`[TC]`、`TC]` |
| `简繁` | 简繁、繁简、CHS&CHT、CHT&CHS、GB&BIG5、BIG5&GB |
| `720p` / `1080p` / `2160p` | 分辨率的两种写法（如 `1080p` 与 `1920x1080`） |
| `Baha` / `ABEMA` | Bahamut / ABEMA 片源标识 |
| `CR` | Crunchyroll、`[CR]`、`(CR)`、`CR `（末尾那个空格是故意的，见下） |
| `B-Global` | B-Global、BGlobal、Bilibili |
| `内嵌` / `外挂` | hardsub / softsub、内封、`[ASS` |
| `MKV` / `MP4` | 容器格式 |
| `合集` | 合集、Batch、BDRip |
| `生肉` | 生肉、无字幕、`[RAW]`、`(RAW)`、`RAW ` |

匹配是大小写不敏感的**子串**匹配，因此有两条容易踩的规则，插件已经替你处理好：

- **双语单文件不会被单语排除项误杀。** `[喵萌][…][简繁日内封]`、`[桜都][…][CHS&CHT]` 这种一个文件里
  同时封了简繁的发布，勾了 `繁体` 也照样推给你 —— 它本来就带着你要的简体，丢掉等于整集收不到。
  真想连双语单文件一起躲，勾 `简繁` 那一组，那是这个豁免唯一的出口。
- **短缩写自带边界，不会误伤正常标题。** 预设里写的是 `[CR]` / `CR ` 而不是裸 `CR`，否则
  `Secret`、`Sacred` 里的 `cr` 都会命中；`生肉` 写的是 `[RAW]` / `RAW ` 而不是裸 `Raw`，
  否则 `[NC-Raws]`、`[Lilith-Raws]` 两个大组的全部发布会被打死；`简体` 只收 `[GB` 而不收 `GB]`，
  否则 `[2.1GB]` 这类体积标注会中招。**自己手写关键词时请照这个思路带上边界。**

会话层的排除词**新加的订阅自动套用**；已经存在的订阅不会被偷偷改写，需要显式 `apply`（或在管理页点「回写到已有订阅」）。
全局层不需要回写 —— 它在每轮轮询时现取，改完立刻对所有订阅生效，包括老订阅。

### 同集归并（默认开启）

一部番订的组固定之后，同一集还是会来好几条。默认做法是**都收下，只推一条**：

- 从标题里认出「哪部番的第几集」（认得出 `第01话`、`S01E05`、`[01]`、`- 01`、`EP01` 等写法）；
- 同一集的多个版本按 `rss_episode_prefer` 打分，只推最合口味的那一条，其余静默跳过并一起记入已读；
- `01v2` 这类修订版永远压过原版；
- 认不出集数的条目（剧场版、合集、字幕组公告）**原样保留** —— 宁可多推一条，也不能让它们互相顶掉。

默认优先顺序是 `简体 > 1080p > Baha > MKV > 外挂`，且**靠前的一项压得住后面所有项之和**：
你把 `简体` 放第一位，就不会因为另一条是「1080p + MKV + 外挂」而收到繁体版。想反过来（先要画质）
就把 `1080p` 挪到最前面。

通知卡片下方会写明「同一集的另外 N 个版本已自动合并」，所以合并了什么不会是黑箱。
不想要这个行为，把 `rss_episode_dedup` 关掉即可。

**归并的语义是「先到先得」，这一点很重要。** 同一个字幕组从 Baha / ABEMA / CR / B-Global 各压一版时，
四版**不是同时发的**，发布时间可能相差几小时，也可能跨天。
所以哪一版先进 feed，推的就是它 —— `rss_episode_prefer` 只在**同一批**里多版本同时到达时才分得出高下。
**想稳定锁定某个片源（例如只要 Baha），靠归并做不到，要用排除项把其它片源挡掉。**

跨天发布还带来第二个问题：光在单次轮询内归并的话，先到的 CR 当轮推走，第二天 Baha 到了会被当成全新条目再推一次，
一集推两遍。`rss_episode_dedup_window_hours`（默认 **48** 小时）解决这个：某一集推过之后，窗口内再到的
同集其它版本静默跳过，通知里会写「另有 N 条是之前推过的那一集的其它版本，已跳过」。
`01v2` 这类修订版不受窗口影响，照推。48 小时是折中值 —— 覆盖得住跨天发布，又短于周更番的 7 天间隔，
不会把下周的同号集误判成重复。填 `0` 表示只在单次轮询内归并。

> 插件不会主动等待尚未发布的版本。若只想要 Baha，应先排除不想要的片源；被排除的 CR 不会占用同集推送名额，Baha 到达后再参与推送。

> 归并只在**同一个字幕组**内部进行，跨组不合并。同一部番订了多个组时请在选源那一步收敛（`/sub 番名` 挑一个组），
> 因为「两个组的第 5 集」在标题上无法可靠判定是同一集，猜错就是静默丢消息。

### 全局层到底该填什么

全局层只填你在**所有订阅里都不要**的版本，例如 `合集`、`720p`。任何排除词都有可能过滤掉一个源的全部发布，保存前请核对实际标题；只针对某条订阅的偏好应放在单条订阅上。

片源（`Baha` / `ABEMA` / `CR` / `B-Global`）该放排除项还是交给归并，**取决于你订的是哪种源**：

| 你的订阅 | 怎么做 | 为什么 |
| --- | --- | --- |
| **单组单番**：用 `/sub 番名` 选源建的，某个组稳定同时发四个片源的版本 | 把不想要的片源填进全局排除项，只留一个 | 这是排除项**最正当的用法**。归并是先到先得，不保证留下你要的那一版；排除项能真正锁定 |
| **宽 feed**：关键词搜索、`dmhy:` 全站源，一条 feed 里混着多个组 | 片源和语言别放全局层，交给同集归并 | 不同组的出片节奏差很多，硬屏蔽片源会让某天整集收不到 |

也就是说，如果你只订了「`[黒ネズミたち]` 的碧蓝之海 3」，而这个组每集都会出 Baha / ABEMA / CR / B-Global 四版，
那么在全局层填 `ABEMA`、`CR`、`B-Global` 只留 Baha，**是正确的填法**，比指望归并挑对更可控。

两个提醒：

- `B-Global` 这个预设展开后含 `Bilibili`，会连带打死 `[Up to 21°C]`、`[NC-Raws]` 这类**简日双语**发布。
  如果你还订着这些组，不要把这个预设放在全局层，改在相关订阅上设置片源排除。预设名也会自动展开，不能靠重复手写同名词绕过展开。
- 语言词（`简体` / `繁体`）**不是一刀切**：只有单语标记（`[CHT]`、`[繁日双語]`、`BIG5`）会被拦，
  `简繁日内封`、`CHS&CHT`、`[CHS][CHT]` 这类双语单文件一律豁免放行。详见上面[三层排除项](#三层排除项)那节。

## 推送顺手回填追番进度

`rss_auto_progress`（默认开）。一条 RSS 更新推送成功后，插件会从标题里解析集号，
把追番表里**标题最接近的那一条**的进度推到该集：

```
[Sub组] 药屋少女的呢喃 第二季 - 07 [1080p][简体]   ← RSS 推送
        ↓ 解析出「07」，标题匹配度 0.72 以上才认
追番列表  药屋少女的呢喃 第二季   6/24  →  7/24     ← 自动往前推一集
```

规则写得比较保守，避免帮倒忙：

- **只往前推。** 已经看到第 10 集，再收到第 7 集的补档不会把进度拽回去。
- **不超过总集数。** 拿到总集数的番，进度最多推到最后一集。
- **一部番只认一条记录。** 同一会话里有多条相似标题时只取匹配度最高的那条，不会一次改一片。
- **已弃坑的不动。** 标成弃坑的番不会因为一条推送就悄悄复活。
- **SP / OVA 不算集数。** 解析不出正整数集号的发布直接跳过。
- **认得出是哪一季。** 「第三季」的更新不会记到第一季的条目上：两边都写了季数、而且不一样时
  直接当成两部番；只有一边没写季数才按同一部处理（表里是 `药屋少女的呢喃`、收到
  `药屋少女的呢喃 第二季` 的更新，仍算同一条）。
- **字幕组的连续编号不会造成假完结。** 年番第三季常常从第 27 集接着编号，硬套「共 12 集」的总集数
  会把进度封成 `12/12`。RSS 回填在编号超出已知总集数 2 集以上时跳过，
  只在管理页近期活动里留一行提醒。

下载器 Webhook（`webhook_auto_progress`，默认开）与 ani-rss 同步共用同一套回填逻辑，三条来源不会互相打架。

表里压根没有这部番时，回填无处可落。所以下载器 Webhook 多做一步：`webhook_auto_watch`（默认开）会先给
**Webhook 通知目标**补一条条目，再在同一次请求里回填进度 —— 见 [Webhook 接入](webhook.md) 一章。

## 推送规则

| 坑 | 处理方式 |
| --- | --- |
| 刚订阅就被推 50 条历史 | `rss_first_poll_silent` 默认开启：首轮只入库不推送 |
| 某个源一次吐出几十条 | `rss_max_items_per_poll` 限流（默认 5 条），超出只记录 |
| 同一条被重复推送 | 去重库按条目唯一标识 + `dedup_window_seconds` 时间窗双重拦截 |
| 源挂了之后每轮都报错刷屏 | 同一个源的错误**只报一次**，恢复后才会再提醒 |
| 高频轮询被目标站封 | 最小间隔硬限制 5 分钟，全局并发上限可配 |
| 去重库越来越大 | 按 `rss_history_days`（默认 14 天）自动清理 |

## 换群不用重配

```
/sub_export          导出成 JSON 文本
/sub_import <JSON>   贴到新群里导入，重名自动跳过
```

追番表也一起导出，搬家很省事。
