下载器最清楚「哪一集刚刚落地」。让它在下载完成时反过来敲插件一下，群里就能第一时间收到带封面的更新卡片，
追番进度也顺手往前推 —— 插件不用轮询任何东西，延迟从「等下一轮 RSS」变成秒级。

**对 ani-rss 用户来说这条路最顺。** ani-rss 一般跑在自己电脑上，让公网服务器主动连回家里的 7789 端口得先打洞；
反过来让 ani-rss 主动推出去，方向天然是对的。

## 1. 开启并设置令牌

配置 → Webhook 接入：

| 配置项 | 填什么 |
| --- | --- |
| `webhook_enabled` | 打开 |
| `webhook_token` | 一串长随机字符串。**不要带英文冒号** —— ani-rss 的请求头是按第一个冒号切开的，值里再有冒号会被截断 |
| `webhook_port` | 一个空闲端口，例如 `9520` |
| `webhook_bind` | 套 Nginx 反代就填 `127.0.0.1`（推荐）；下载器直连才填 `0.0.0.0` |
| `webhook_auto_progress` | 默认就是开的。追番进度会跟着「下载完成」往前走 |
| `webhook_auto_watch` | 默认就是开的。第一次推过来的番会自动进追番表，不必先手动 `/追番` |

> **安全约束：** `webhook_port > 0` 但 `webhook_token` 为空时，监听服务会**拒绝启动**并在日志里报错。
> 这是故意的 —— 一个不校验令牌的公网端口等于让任何人往你群里发消息。

## 2. 选一条通道

| 通道 | 地址 | 什么时候用 |
| --- | --- | --- |
| 面板路由 | `http(s)://<AstrBot>/api/plug/bangumi_nexus/notify` | 面板自测用。**这条路由受 Dashboard 登录态保护**，外部程序直连会 401 |
| 独立端口 | `http://<AstrBot主机>:<webhook_port>/<webhook_path>` | 局域网内直连。插件会额外起一个只处理 Webhook 的极简 HTTP 服务 |
| 反代域名 | `https://<你的域名>/<webhook_path>` | **公网推送首选**，见第 4 步 |

## 3. ani-rss 里怎么填

ani-rss 设置 → 通知 → 新增一条，类型选 **WebHook**。

**请求方式**：`POST`

**WebHook 地址**：第 2 步选好的那个完整地址，例如 `https://bangumi.example.com/bangumi_nexus/notify`

**请求头**（每行一条 `键: 值`，值里不能再有冒号）：

```
Content-Type: application/json
X-Webhook-Token: 你在第 1 步设的令牌
```

**消息内容（Body）**：

```json
{"event":"${action}","title":"${title}","season":"${season}","episode":"${episode}","currentEpisodeNumber":"${currentEpisodeNumber}","totalEpisodeNumber":"${totalEpisodeNumber}","poster_url":"${image}","url":"${bgmUrl}","subgroup":"${subgroup}","score":"${score}","message":"${message}"}
```

**集数字段的含义**：

| 字段 | 含义与用途 |
| --- | --- |
| `${episode}` | 本次通知文本中的集号，可能已经过 ani-rss 的集数偏移。用于本次通知。 |
| `${currentEpisodeNumber}` | 整个订阅的统计值，按设置可能是最大集号或资源条数。只作参考，不作为本次集数或回填依据。 |
| `${totalEpisodeNumber}` | 总集数，用于卡片展示和编号校验。 |
| `${bgmUrl}` | 对应这一季的 Bangumi 条目链接，用于封面、总集数和连续编号核对。 |

例如：订阅统计已到 10，这次补下第 8 集，通知显示第 8 集，而不是第 10 集。

当本次编号超出总集数时，插件尝试从对应 Bangumi 分集表找到明确的 `sort → ep` 映射，
例如 `27 → 3`。有订阅统计也会核对；没有明确映射时显示源编号及「本季集数未确认」，不回填进度。
插件不根据分集表的数组位置猜编号。正常季内编号直接保留，避免再次应用 ani-rss 已做过的偏移。

`12.5` 等小数集数会保留显示，不作为第 12 集或第 13 集写入正片进度。补下旧集不会使已有进度倒退。
人格播报仅接收本次确认的集数；可识别的错误集数会被拦截，重试失败时按 `persona_fallback_line` 配置兜底。

请核对 `${bgmUrl}` 指向正确季度。总集数未知、上游已填错集号，或连续编号仍在本季总集数范围内时，
插件无法仅凭一个数字可靠判别编号体系，应先在 ani-rss 校正订阅和偏移。

> ⚠️ **每个占位符都要用引号包住，`${message}` 也一样。**
> ani-rss 只帮你转义 `${message}` 的内容（引号、换行都处理好了），**但不会替你补外层引号** ——
> 少这一对，整个 Body 就不是合法 JSON，插件只能回 `400`，你那头看到的就是「通知失败」。
> `${season}` / `${episode}` 展开出来是裸数字，同理必须加引号。
>
> 模板保持使用 `${message}` 即可；
> `${title}` `${subgroup}` 这些也是原样替换，所以番名里真带英文双引号时同样会撑坏 JSON。
> 插件会尝试兼容部分不规范的 Body，并在 AstrBot 日志里提醒你改模板 ——
> 但能修的形状有限，模板还是照上面这份抄最稳。

**通知状态**（最容易漏的一步）：ani-rss 默认只勾「开始下载 / 缺少集数 / 发生错误」，
**「下载完成」默认是没勾的** —— 不勾它，进度回填永远不会触发。建议至少勾上「开始下载」和「下载完成」，
其余按需。

填完点 ani-rss 自带的「测试」按钮，管理页「概览 → 活动日志」里应该立刻多出一条 Webhook 记录。

## 4. 套上域名和 HTTPS（推荐）

裸 IP 加 HTTP 传令牌是明文的，路上任何一跳都看得见。有域名的话花五分钟套一层反代，收益很大：

```
ani-rss（你家电脑）──HTTPS──▶ Nginx:443（你的域名）──▶ 127.0.0.1:9520（插件监听）
```

三个好处：令牌走加密信道；`9520` 收回内网、防火墙/安全组不用对外开；端口扫描器看不到它。

Nginx 配置（Debian / Ubuntu 放 `/etc/nginx/sites-available/`，再软链到 `sites-enabled/`）：

```nginx
server {
    listen 80;
    server_name bangumi.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name bangumi.example.com;

    ssl_certificate     /etc/letsencrypt/live/bangumi.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/bangumi.example.com/privkey.pem;

    # 只放行 Webhook 这一条路径
    location = /bangumi_nexus/notify {
        proxy_pass http://127.0.0.1:9520;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        client_max_body_size 1m;
    }

    location / { return 444; }
}
```

证书用 certbot 一条命令签：`certbot --nginx -d bangumi.example.com`（DNS 要先解析到这台机器）。
配好之后把 `webhook_bind` 改成 `127.0.0.1`，ani-rss 地址换成域名版。

> `location =` 是精确匹配，其它路径一律 444 直接断开。这样即使域名被人扫到，对方也只能看到一个要令牌的接口。

## 5. 一集别刷两条：静默事件

「开始下载」和「下载完成」都勾上，一集自然会来两条。想两个事件都收、但只想看一张卡片，
把不想看的那个填进 `webhook_silent_kinds`：

```
webhook_silent_kinds = ["下载完成"]
```

静默的事件**照常回填追番进度**、照常记进活动日志，只是不发卡片。
反过来填 `["开始下载"]` 也行 —— 取决于你想在「开始下」还是「下完了」的那一刻收到提醒。

## 6. 认得出哪些事件

| ani-rss 动作 | emoji | 插件事件 | 回填进度 | 卡片语气 |
| --- | --- | --- | --- | --- |
| 开始下载 | 🎈 | `download_start` | — | 普通 |
| 下载完成 | 🎉 | `download_complete` | ✅ | 普通 |
| 缺少集数 | ⛔ | `episode_missing` | — | 警告 |
| 发生错误 | ❌ | `download_error` | — | 警告 |
| 订阅完结 | 🎊 | `series_completed` | — | 普通 |
| 摸鱼检测 | 🐟 | `idle_warning` | — | 普通 |
| 整理完成（AutoBangumi） | — | `rename_complete` | ✅ | 普通 |

中文动作名、emoji、英文标识三种写法都认，**混在一起也认** —— 有人图省事在模板里写
`"event": "${emoji}${action}"`，出来是 `🎉下载完成`，插件照样能折回 `download_complete`。
空格、连字符、方括号（`download complete` / `Download-Complete` / `[下载完成]`）同样处理。
万一都对不上，插件会看字段自己推断（有 `error` 字段当失败、带集数当新集），不会把这条请求直接丢掉。

没给 `episode` 字段也没关系：ani-rss 的 `${message}` 里天然带着 `S01E05` 这种串，插件会从里面把季/集抠出来。
封面是 ani-rss 的占位图（`null.png`）时会自动丢掉，改去 Bangumi 拿一张真海报。

## 7. 插件会回什么状态码

排查时对着这张表看，比翻日志快：

| 状态码 | 含义 | 该怎么办 |
| --- | --- | --- |
| `200` | 收下了，卡片也发完了 | 正常 |
| `202` | **收下了，卡片正在后台生成** | 正常，见下方说明 |
| `400` | Body 不是合法 JSON，或者缺了必要字段 | 十次有九次是模板里 `${message}` 没被引号包住。AstrBot 日志里会打出出错位置和原文开头，照着改 |
| `401` | 令牌不对或没带 | 核对请求头 `X-Webhook-Token`，注意值里不能有冒号 |
| `404` | 路径不匹配 `webhook_path` | 地址少写/多写了一层，注意大小写与尾斜杠 |
| `405` | 用了 GET 之外的非 POST 方法 | 请求方式改成 `POST` |
| `408` | 请求头/请求体没写完就发呆了 | 一般是网络中断，重试即可 |
| `413` | Body 超过 256 KB | 模板里别塞完整日志 |
| `429` | 触发反代的限流 | Nginx 的 `limit_req`，等一会儿再推 |
| `500` | 插件内部异常 | 看 AstrBot 日志，或到管理页「概览 → 活动日志」看那一条 |

顺带一提，这条路径也接受不带令牌的 `GET`，回一个 `{"ok": true, "ready": true}` 的存活探针，
方便用 `curl` 或监控面板确认「端口通不通、反代有没有配对」，不会泄露任何业务信息。

**关于 `202`：** 一条「下载完成」的完整链路是拉封面 → 调人格 LLM 转述 → 渲染卡片 → 逐会话发送，
接了慢一点的模型时 20~30 秒很正常，而 ani-rss 只关心「有没有被收下」，等太久会判失败甚至重推。
所以插件等到 8 秒还没跑完就先回 `202「已受理」`，剩下的活在后台照常跑完 ——
**你会照常收到卡片，进度照常回填**。管理页「通知与 Webhook」里能看到累计转后台了多少条。
## 8. 卡片会发给谁

Webhook 的收件人 = **固定目标** ∪ **追番表里收录了这部番的会话**（后者由 `webhook_notify_watchers` 控制）。

固定目标先看 `webhook_targets`，留空才退回每日播报的 `push_targets`。分成两个字段是因为这两条链的
收件人常常不一样：下载完成属于流水账，多数人想丢进某个群；每日播报更适合留在私聊。共用一份名单的话，
想把下载通知挪进群就得连带把播报也挪走。

| 我想要的效果 | 怎么填 |
| --- | --- |
| 两条链都发同一批人 | `webhook_targets` 留空即可，自动沿用 `push_targets` |
| 下载通知只进 A 群，播报留私聊 | `webhook_targets` 填 A 群，`push_targets` 填私聊 |
| **严格只发** `webhook_targets` 里这几个会话 | 再把 `webhook_notify_watchers` 关掉，否则追了这部番的会话会额外收到 |

管理页 **「播报」→「Webhook 通知目标」** 里有这份名单的可视化编辑器，也会告诉你当前是「专用名单」
还是「沿用播报目标」。

> **一个刻意的不对称：** 卡片发给上面这一整批人，但「自动加入追番表」（下一节）**只在固定目标里建条目**。
> 追番联动派生出来的会话正是因为表里已经有这部番才收到通知，不需要再建；往陌生会话里写数据更是越权。

## 9. 追番联动与进度回填

- `webhook_notify_watchers`（默认开）：除固定目标外，**追番表里收录了这部番的会话**也会收到通知。
  一台下载器服务好几个群时，各群只收自己关心的番。
- `webhook_auto_watch`（**默认开**）：某部番第一次推过来、而**固定目标**的追番表里还没有它时，自动补一条，
  接着在同一次请求里回填进度 —— 不用先去聊天窗口 `/追番` 一次。卡片正文会多一行「已自动加入追番表」，
  好让你知道表里为什么多了一条。四条边界：
  ① **只给固定目标建**（`webhook_targets`，留空则 `push_targets`），追番联动派生出来的会话本来就有条目，不会被写入；
  ② 标题模糊匹配得上就算已有，不会出现「XX」和「XX 第二季」两条；但**两个明确且不同的季度**
  （「XX 第二季」与「XX 第三季」）会各立一条 —— 它们集数、进度、封面都不一样，混在一起只会两头都不对；
  ③ **弃坑的不复活** —— 你主动弃掉的番不会被一条下载通知拉回来；
  ④ Bangumi 搜不到（冷门番、只给了日文原名、网络抖动）也会建一条只有名字的记录，绝不静默跳过。
- `webhook_auto_progress`（默认开）：新集入库时自动把追番进度推到该集。只往前推、不超总集数，
  不会降低你手动填写的较高进度；若要只手动记进度，请关闭自动回填。**和上一项是两个独立开关** —— 想「只建清单、进度自己点」或者
  「只记进度、别动我的清单」都行。
